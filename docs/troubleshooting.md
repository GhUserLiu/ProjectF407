## 快速诊断

### 诊断清单

遇到问题时，按以下顺序检查：

- [ ] 程序是否为最新版本？
- [ ] Windows 是否为 64 位？
- [ ] VC++ 运行库是否已安装？
- [ ] 杀毒软件是否拦截？
- [ ] 磁盘空间是否充足？
- [ ] 路径是否包含中文或特殊字符？
- [ ] 文件权限是否正确？

### 收集诊断信息

在报告问题时，请提供以下信息：

1. **系统信息**
   - Windows 版本
   - 程序版本
   - 安装方式

2. **错误信息**
   - 完整的错误提示
   - 错误发生时的操作

3. **日志文件**
   - 位置：`%APPDATA%/STM32教学管理系统/`
   - 文件：`stm32_manager.log`

## 启动问题

### 问题 1: 程序无法启动

#### 症状
- 双击程序无反应
- 程序闪退
- 任务管理器中有进程但无界面

#### 原因分析
```
可能原因:
├── 缺少 VC++ 运行库 (最常见)
├── 杀毒软件拦截
├── 权限不足
├── 程序文件损坏
└── 系统不兼容 (32位系统)
```

#### 解决方案

**方案 A: 安装 VC++ 运行库**
1. 下载：https://aka.ms/vs/17/release/vc_redist.x64.exe
2. 运行安装程序
3. 重启计算机

**方案 B: 添加杀软白名单**
1. 打开杀毒软件
2. 将程序目录添加到白名单
3. 重新运行程序

**方案 C: 以管理员身份运行**
1. 右键程序
2. 选择"以管理员身份运行"

**方案 D: 重新安装**
1. 完全卸载程序
2. 删除配置目录
3. 重新安装

---

#### 症状

## 功能异常

### 问题 3: 查重检测失败

#### 症状
- 点击开始后无反应
- 进度卡住不动
- 结果为空

#### 诊断流程

```
开始
  ↓
检查提交目录是否存在? ───否──→ 配置正确的目录
  ↓ 是
检查是否有 ZIP 文件? ───否──→ 确认学生已提交
  ↓ 是
检查 ZIP 命名格式? ───否──→ 重命名或调整设置
  ↓ 是
检查 ZIP 是否损坏? ───是──→ 重新打包
  ↓ 否
检查模板文件? ───异常──→ 重新选择模板
  ↓ 正常
联系技术支持
```

#### 解决方案

**情况 A: 结果为空**
- 确认提交目录有文件
- 检查文件命名格式
- 尝试降低阈值

**情况 B: 处理卡住**
- 检查是否有超大文件
- 减少同时处理的文件数
- 查看日志文件

**情况 C: 相似度全部 100%**
- 启用模板过滤
- 上传正确的模板文件

### 问题 4: 评分结果异常

#### 症状
- 评分全部为 0
- 评分分布不合理
- 程序崩溃

#### 诊断步骤

**步骤 1: 检查 Rubric 文件**
```json
// 验证 JSON 格式是否正确
// 使用在线工具验证：https://jsonlint.com/
```

**步骤 2: 检查提交文件**
- 确认是 DOCX 格式
- 确认文件可以正常打开
- 检查文件是否损坏

**步骤 3: 检查评分权重**
- 确认权重总和为 1.0
- 调整各项权重比例

### 问题 5: 报告生成失败

#### 症状
- 点击生成无反应
- 文件生成但打不开
- 内容乱码

#### 解决方案

**方案 A: Excel 报告问题**
- 确认安装了 openpyxl
- 检查输出目录权限
- 尝试选择不同的输出位置

**方案 B: PDF 报告问题**
- 确认安装了 reportlab
- 检查中文字体支持
- 尝试导出 HTML 格式

## 性能问题

### 问题 6: 处理速度慢

#### 症状
- 处理大量文件时速度慢
- 界面卡顿
- 内存占用高

#### 优化建议

**优化 1: 调整线程数**
```
设置 → 系统设置 → 线程数
├── CPU 核心数 ≤ 4: 设置为 2
├── CPU 核心数 4-8: 设置为 4
└── CPU 核心数 ≥ 8: 设置为 6-8
```

**优化 2: 分批处理**
- 每次处理不超过 50 个文件
- 处理完成后重启程序

**优化 3: 禁用不必要的功能**
- 关闭语义检测（如不需要）
- 关闭代码混淆检测

---

### 问题 7: 内存占用过高

#### 症状
- 内存使用超过 2GB
- 系统变慢
- 程序崩溃

#### 解决方案

**方案 A: 重启程序**
- 处理完成后关闭程序
- 重新启动处理下一批

**方案 B: 使用目录打包模式**
- 目录模式启动更快
- 内存占用更低

**方案 C: 禁用大文件处理**
- 过滤超过 10MB 的文件

## 数据问题

### 问题 8: 配置丢失

#### 症状
- 重启后设置丢失
- 项目配置重置

#### 预防措施

**方法 1: 定期导出配置**
```
设置 → 导出配置
保存为: config_backup.json
```

**方法 2: 使用备份功能**
```
设置 → 备份数据
自动打包所有数据
```

#### 恢复方法

1. 使用 **导入配置** 功能
2. 从备份 ZIP 中提取配置
3. 手动重新配置

---

### 问题 9: 文件路径问题

#### 症状
- 找不到文件
- 路径错误

#### 最佳实践

**路径命名规则：**
```
✓ 推荐:
  D:\教学\2026春\07-car-gear
  C:\STM32_Projects\实验01

✗ 避免:
  D:\教学\2026春\档位实验
  D:\教学\新建文件夹 (1)
  包含空格和特殊字符的路径
```

**建议：**
- 使用英文路径
- 避免空格和特殊字符
- 路径不要太深（建议不超过 5 层）
